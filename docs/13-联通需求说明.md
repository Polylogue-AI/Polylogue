# 联通：需求说明

> 读者：接手这项功能的 Aaron，以及他使用的 AI 助手。
> 本文写的是**要做成什么样、已经定下的条件和底线**。接口契约（v0.8）和具体实现由接手方设计。动手写代码前，先按 `docs/02-分工与协作流程.md` 的流程更新 `docs/03-接口契约.md`。

## 1. 要解决什么问题

现在的 Polylogue 里，所有模型都由服务器统一调用，只能说话，或者在服务器的 Docker 沙箱里跑一段代码。它们碰不到任何人电脑上的真实项目。

"联通"要做到：**两个人可以互相使用对方电脑上的 Agent（例如 Claude Code、Codex、Gemini CLI），共享上下文，互相修改项目文件。** 第一版只考虑两个人。

使用场景举例：
- Eutopia 在房间里 @"Aaron 的 Claude Code"，让它读 Aaron 电脑上的项目、回答问题、做代码审查。
- Aaron 的 Agent 改完代码并跑通测试，Eutopia 的 Agent 拉下改动，在此基础上继续写，两个人在房间里审核、合并。

## 2. 已经定下的条件

这些是项目发起人 Eutopia 确认过的，改动前请先和他商量。

| # | 条件 | 说明 |
|---|---|---|
| 1 | **部署在服务器上** | 两个人的电脑都连同一台服务器，不用 Tailscale 之类的点对点组网。所以部署配置（HTTPS、反向代理、一键启动、部署说明）属于这项工作的一部分，目前仓库里还没有 |
| 2 | **Agent 先用 API Key** | 订阅账号（Claude Pro/Max 等）以后再接。原因之一：个人订阅一般只允许本人使用，让别人通过你的订阅跑任务，可能违反服务条款 |
| 3 | **共享的是代码和文档文件** | 不只是代码仓库，文档也要能读、能改 |
| 4 | **第一版功能和 Agent 客户端基本持平** | 读取、修改、上传、运行命令都要有，不是只读起步 |
| 5 | **"运行命令"的控制方式** | 见第 4 节 |
| 6 | **两个人之间的文件传输不单独做** | 代码和文档靠 Git 同步；不在仓库里的零散文件（图片、PDF 等）通过"上传"进入房间 |

## 3. 建议的架构（供参考，可以改）

参考了一些已有做法后，否决了两种思路：
- **区块链 / 去中心化，Agent 之间直接通信、人不介入**：两个熟人加一台自己的服务器，不存在信任问题，区块链只会增加延迟、成本和复杂度。人不介入也不能规避责任：Agent 改的是你的文件，出了事责任还在机器主人身上。
- **为 Agent 发明专用语言来降低推理成本**：现阶段没必要。真正省钱的办法是少传重复的上下文：传摘要、传文件差异，而不是整段对话。

采用的思路：**官方 SDK / CLI + 服务器中转 + 共享会话记忆**。

```
 Eutopia 的电脑                     服务器（Polylogue）                      Aaron 的电脑
┌──────────────────┐   主动连出   ┌──────────────────────┐   主动连出   ┌──────────────────┐
│ 本地节点          │ ──WebSocket──▶│ 房间：共享上下文     │◀──WebSocket── │ 本地节点          │
│  └ Agent（API Key）│              │ 任务转发、权限、审计 │              │  └ Agent（API Key）│
│  └ 项目目录（git） │              │ 文件改动记录         │              │  └ 项目目录（git） │
└──────────────────┘              └──────────────────────┘              └──────────────────┘
```

- **本地节点**：每人电脑上运行的小程序。它主动连接服务器，所以不需要公网 IP，也不用做端口映射。它向服务器登记本机有哪些 Agent、各自绑定哪个项目目录；接收任务交给 Agent 执行；把执行过程（输出、读写了哪些文件、运行了哪些命令）实时传回房间。
- **Agent 的调用方式**：用官方 SDK 或 CLI 的非交互模式，例如 Claude Agent SDK（支持流式输出、权限回调、续接会话）、Codex 和 Gemini 的命令行。具体参数请以官方文档为准。
- **房间里的新成员类型"远程 Agent"**：例如"Aaron 的 Claude Code（polylogue 项目）"，可以像现有 AI 成员一样被 @、被分配任务，只是实际在 Aaron 的电脑上执行。执行过程在房间里显示成卡片，可以参考现有的代码运行卡片（`frontend/src/components/RunCard.tsx`）。
- **共享上下文分三层**：
  1. 房间记录：现有的讨论历史，已经实现。
  2. 交接摘要：Agent 每完成一个任务，自动写一段"做了什么、改了哪些文件、还剩什么"发到房间。下一个 Agent 读摘要，不读对方的整段会话。
  3. 项目记忆文件：项目里放一份共享笔记（约定、决定、待办），两边的 Agent 都读写，跟着 Git 同步。
- **文件修改走 Git**：两个人各有同一仓库的副本。远程 Agent 在单独的分支上工作（例如 `rt/<任务名>`），完成后提交、推送；房间里显示改动内容，由机器主人合并或退回；另一方的 Agent 接手前先拉取这个分支。这样每次改动都可审查、可回退，冲突交给 Git 处理。不建议做实时同步文件夹。

## 4. 安全底线（第一版必须有）

第一版就开放修改和运行命令，下面这些**不能**留到以后：

| 项目 | 要求 |
|---|---|
| 只开放指定目录 | 机器主人在本地节点里明确选择哪个目录开放给谁。Agent 访问不到其他目录，也访问不到 `.env`、密钥这类机密文件 |
| 权限分级 | 每个开放给对方的 Agent 单独设置：能否读、能否改文件、能否运行命令 |
| 运行命令分三档 | ① 不能运行；② 每条命令运行前都要主人批准；③ 白名单里的命令（如 `npm test`、`pytest`）直接运行，其余仍要批准。**默认第 ② 档** |
| 运行命令的范围 | 只在开放的项目目录里运行，有超时，主人可以随时终止 |
| 危险操作审批 | 删除文件、运行命令、推送代码等操作弹到主人那边确认。主人不在线就暂停等待，不自动通过 |
| 一键断开 | 主人随时可以断开，正在执行的任务立即停止 |
| 全程留痕 | 谁在什么时候让哪个 Agent 做了什么、改了什么、运行了什么命令和输出，都记在房间里 |
| 费用上限 | Agent 用的是机器主人的 API Key，每个任务、每人每天都要能设上限 |

第一版之后再做：Agent 和命令默认在 Docker 容器里运行，只挂载项目目录。现有沙箱（`backend/app/sandbox.py`）的隔离参数可以参考。

## 5. 第一版完成的标准

两个人分别在自己的电脑上运行本地节点，连到同一台部署好的服务器，然后：

1. 在房间里能看到对方的远程 Agent，能 @ 它、给它分配任务。
2. 对方的 Agent 能读取开放目录里的代码和文档并回答问题。
3. 能修改文件。改动在单独分支上提交，房间里能看到改动内容，主人能合并或退回。
4. 能运行命令（测试、构建），默认每条都要主人批准，输出显示在房间里。
5. 能把图片、PDF 等文件上传到房间，两边的 Agent 都能读。
6. 一个 Agent 的工作成果（交接摘要 + 分支）能被另一方的 Agent 接着用。
7. 第 4 节的安全底线全部生效，并有对应的测试。
8. 有部署说明，按说明能在一台新服务器上把整套系统跑起来。
