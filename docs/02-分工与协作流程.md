# 分工与协作流程

## 角色

| 谁 | 负责 | 不碰 |
|---|---|---|
| **你**（项目负责人） | 定需求和优先级；在 Claude 和 ChatGPT 之间传递代码和文档；配置 API Key；用真实任务试用并反馈 | — |
| **Claude** | 整个前端（`frontend/`）；接口契约的起草和维护；前端自带的模拟后端；审查 ChatGPT 交付的后端代码 | `backend/` 下的业务代码（只提审查意见，不直接改） |
| **ChatGPT** | 整个后端（`backend/`）：模型接入、编排引擎、四种模式、房间与 WebSocket、存储、登录、预算、上下文压缩；`docker-compose.yml`；审查 Claude 的前端代码 | `frontend/` |
| **共同** | `prompts/` 下的角色提示词（Claude 起草唱反调、汇总者、裁判；ChatGPT 起草规划者、执行者、审查者），互相审一遍 | — |

这样分的理由：前后端之间只隔着一份接口契约，两边可以并行开发，互不阻塞。前端靠模拟后端先跑起来，后端靠契约和自动化测试验收，最后对接时只需要把 `VITE_MOCK` 关掉。

两个模型互相审查对方的代码，本身就是这个产品想验证的"交叉验证"。

## 里程碑与分工

| 阶段 | Claude（前端） | ChatGPT（后端） | 对接验收 |
|---|---|---|---|
| **M1 原型**（1 周） | ✅ 已完成：接口契约 v0.1、前端骨架、模拟后端、登录 / 房间列表 / 圆桌房间 / 成员 / 用量页面 | `llm.py`（LiteLLM 流式调用 + 费用）、圆桌模式命令行版 | 命令行输入一个问题，3 家模型讨论 2 轮后汇总，打印总费用（开发方案第 7 节的验收标准） |
| **M2 可用**（2–3 周） | 根据后端实际表现调整；设置页（模型服务状态、邀请码）；断线重连的提示 | FastAPI + WebSocket 房间、SQLite、邀请码登录、预算检查、REST 全部接口 | 关掉 `VITE_MOCK`，两个浏览器窗口登录不同的人进同一房间，能同时看到流式输出，能插话、@、暂停、打断 |
| **M3 协作**（2–3 周） | 流水线、交叉验证、辩论界面的细节打磨（界面已先做好） | 流水线、交叉验证（含匿名互评）、辩论；上下文压缩；`steer` | 四种模式各用一个真实任务跑通 |
| **M4 增强** | 知识库、工具开关界面 | RAG、工具调用 | 按需 |

## 交接流程

```
  ChatGPT 写后端                           Claude 写前端
       │                                        │
       └──────→  你把代码放进 backend/  ←───────┘
                        │
                  Claude 跑测试、审查，
                  意见写进 docs/review/
                        │
            你把审查意见转给 ChatGPT 修改
```

1. **开工**：把 `docs/04-给ChatGPT的任务书.md` 和 `docs/03-接口契约.md` 两份文件发给 ChatGPT。
2. **交付**：ChatGPT 每完成一个模块，给出完整文件（不要只给片段）。你把文件放进 `backend/` 对应位置。
3. **审查**：回到 Claude 这边说"审查后端"，Claude 会运行测试、对照契约检查，把问题写进 `docs/review/后端-日期.md`。你把这份文件转给 ChatGPT。
4. **反向审查**：同样可以把 `frontend/src/` 发给 ChatGPT 审查，意见转回 Claude。
5. **改契约**：任何一方觉得契约要改，先提出修改内容。你同意后，由 Claude 更新 `03-接口契约.md` 的版本号和变更记录，再通知另一方。**不要让任何一方私下改字段。**

## 冲突时听谁的

- 接口字段、事件格式：以 `03-接口契约.md` 为准。
- 产品行为（例如插话后谁先说话）：以契约第 3.4 节为准，契约没写的由你决定。
- 技术选型：以《AI协作集群-基于开源的开发方案.md》为准。
