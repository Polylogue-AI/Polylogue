## 必修

### 1. 汇总者是最后一位发言者时，提示词以 assistant 消息结尾

`context.py` 把说话人自己以前的发言标成 `assistant`。默认汇总者是最后一位成员（契约规定），所以汇总那一轮的 messages 最后一条正好是它自己刚说的话：

```
system: 你是 DeepSeek……汇总讨论……
user:   [讨论主题]：……
...
assistant: [DeepSeek（风险与汇总）]：（第 2 轮刚说的话）   ← 最后一条
```

Anthropic 会把结尾的 assistant 消息当作"预填"，让模型接着这段话往下写，而不是开始汇总；有些新模型直接拒绝预填，返回 400。其他厂商的处理方式也不一致。`--fake` 和现有测试都发现不了：`test_history_and_explicit_summarizer` 指定了 `ai_a` 汇总，最后一条刚好是 user。

**改法**：`build_context` 末尾固定追加一条 user 消息，写明"现在轮到你（名字），本轮要求：……"，把 `Turn.instruction` 里本轮目标那部分移到这里；system 里只保留角色设定。补一个测试：默认汇总者时，最后一条消息的 role 是 `user`。

## 建议本批修改

### 2. 发言被截断成 `max_chars`

`roundtable.py:97` 用 `[:member.max_chars]` 截断模型的输出。任务书第 3.6 条的要求是：字数上限写进提示词，用 `max_tokens` 兜底，没有要求截断。截断会让句子停在半截。到了第二批会更麻烦：前端已经逐字显示了完整内容，`message_end.content` 却比显示的短，界面上的文字会突然缩回去。

**改法**：删掉截断，保留模型的原始输出。

### 3. 费用计算里的异常可能盖掉原来的异常

`llm.py` 在 `finally` 里调用 `stream_chunk_builder`、`token_counter`、`completion_cost`，只捕获了 `NotFoundError`。这些函数遇到没在价格表里的模型或格式不对的数据时，还可能抛别的异常。异常从 `finally` 里抛出，会替换掉原来的异常。第二批靠 `task.cancel()` 实现打断，到时 `CancelledError` 会被换成一个莫名其妙的错误，打断就失效了。

**改法**：把整段用量计算包进 `try/except Exception`，失败时 `cost = None`，tokens 用估算值，绝不在 `finally` 里抛异常。

### 4. 命令行脚本的模型名和错误信息

- `.env.example` 里的 `gemini/gemini-3.5-flash-lite` 和 `deepseek/deepseek-flash`，请确认它们在当前 LiteLLM 版本的价格表里存在。不在的话，M1 验收标准要求的"打印总费用"只会显示"未能计算"。
- `cli.py:69` 出错时只打印异常类型，例如"模型调用失败（AuthenticationError）"，看不出是哪个模型、什么原因。请同时打印模型名和异常信息（LiteLLM 的异常信息里不含完整 Key）。
- `cli.py:25` 写死检查三个 Key。换了模型（比如把 Gemini 换成 OpenAI）就会误报。可以用 `litellm.validate_environment(model)` 按实际模型检查。

## 第二批开工前要先改的设计

### 5. `Roundtable.discuss()` 的结构撑不起插话、打断和 @

现在的流程是：开始前用 `turns()` 一次性排好全部发言顺序；每次把整段输出收完，再 `yield` 一个完整的 `Speech`。第二批需要的几件事它都做不到：

| 第二批的要求（契约第 3.4 节） | 现在的结构 |
|---|---|
| 逐字推送 `message_delta` | 输出收完才交出来 |
| 打断、跳过：取消正在进行的流 | 调用方拿不到正在进行的流 |
| 被 @ 的 AI 排到下一位 | 发言顺序在开始前就定死了 |
| 下一位 AI 先回应人的插话 | 历史记录里只有 AI 的发言 |

任务书第 2 节要求的 Mode 接口是 `next_speaker()` / `build_prompt()` / `on_message_end()`：每次发言前问一次"下一位是谁"，循环本身放在 `orchestrator.py`。请按这个接口把圆桌模式重写，`turns()` 的排序逻辑可以留作 `next_speaker()` 的默认顺序。`llm.py` 的 `ChatStream` 已经能逐字迭代、能 `aclose()`，这部分直接沿用。

另外两个小点，第二批一起做：

- 契约要求模型调用失败时**重试 1 次**，仍失败就发 system 消息并跳过这位成员。现在没有重试，一个模型出错整场讨论就中断。
- 历史记录现在是 `(id, label, text)` 元组。第二批要加人的发言、`steer`、摘要，建议直接改用和契约 `Message` 对应的数据类。

## 做得好的地方

- `LLM` 用 Protocol 定义，`FakeLLM` 和 `LiteLLM` 可以互换，测试不用联网。
- `ChatStream` 关闭后才填 `usage`，被中途关闭时也会按已输出部分计费（`test_fake_stream_yields_characters_and_reports_partial_usage` 覆盖了这种情况），正是第二批"打断后按已产生 tokens 计费"需要的。
- 金额全程用 `Decimal`，统一四舍五入到 4 位小数，和契约一致。
- 没有引入任何编排框架，依赖只有 `litellm` 和 `python-dotenv`。
