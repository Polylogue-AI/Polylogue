第一批收到了，`--fake` 能跑，4 项测试通过。Claude 审查过代码，意见在附件《后端-2026-11-22.md》里。结论是有条件通过，有一个必修问题：

**汇总那一轮，发给模型的 messages 最后一条是汇总者自己上一轮的发言（assistant 角色）。** 默认汇总者是最后一位成员，汇总时它刚说完第 2 轮。Anthropic 会把结尾的 assistant 消息当作预填，让模型续写自己的话，有些模型会直接返回 400。现有测试指定了第一位成员汇总，所以没发现。请让 messages 最后固定追加一条 user 消息，写明"现在轮到你，本轮要求……"，并补一个默认汇总者的测试。

另外，契约已更新到 **v0.2**，变更记录在契约末尾。和你相关的是：
- 新增**假模型模式** `LLM_MODE=fake`：不需要任何 Key 就能启动后端，前端对接用这个模式
- 新增邀请码管理接口 `/api/invites`，补充了邀请码格式和绑定规则
- 成员的增删改只有管理员可以调用
- 明确了**不截断**模型输出

这一批先不接真实 API，开发和测试都用假模型。请按任务书"第二批"一节的顺序做：

1. 修审查意见的第 1–3 条。第 4 条只改报错信息和按实际模型检查 Key，模型名核对以后再做。
2. 按审查意见第 5 条，把圆桌模式改成 `next_speaker()` / `build_prompt()` / `on_message_end()` 接口，编排循环放进 `orchestrator.py`。
3. 假模型模式、数据库、登录、全部 REST 接口、WebSocket 房间、预算、重试。
4. 任务书里列的 9 个测试场景。
