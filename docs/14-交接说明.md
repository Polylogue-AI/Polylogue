# 交接说明

> 读者：新加入的 Aaron，以及他使用的 AI 助手。读完这份，再读 `docs/03-接口契约.md` 和 `docs/13-联通需求说明.md`，就可以开始工作了。

## 1. Polylogue 是什么

几个 AI 模型和几个朋友坐在同一个"房间"里，一起把事情想清楚、做出来。支持四种协作方式：

| 模式 | 做法 |
|---|---|
| 圆桌讨论 | 每位成员轮流发言若干轮，最后一位汇总 |
| 分工流水线 | 规划者拆任务 → 执行者完成 → 审查者通过或退回 → 汇总 |
| 交叉验证 | 同一个问题同时问多个模型，匿名互评，裁判给出共识和分歧 |
| 辩论 | 正方、反方轮流发言，裁判每轮打分，最后裁决 |

面向小团队私用，规模大约 2–10 人，邀请码登录。

## 4. 在本地跑起来

**只看界面（不需要后端和 Key）**

```bash
cd frontend
npm install
echo "VITE_MOCK=1" > .env
npm run dev                # http://localhost:5173，任意 6 位邀请码，名字填"林"就是管理员
```

**前端 + 假模型后端（不需要 Key，不花钱）**

```bash
cd backend
python -m venv .venv && source .venv/bin/activate   # Windows：.venv\Scripts\activate
pip install -e ".[test]"
LLM_MODE=fake python -m uvicorn app.main:app --port 8000   # 管理员邀请码默认是 TABLE2

# 另开一个终端
cd frontend
echo "VITE_MOCK=0" > .env
npm run dev
```

**真实模型**

1. 复制 `backend/.env.example` 为 `backend/.env`，填上**你自己的** Key，把 `LLM_MODE` 改成 `real`，并把 `ADMIN_INVITE_CODE` 改成你自己的（6 位，字母 + 数字 2–9，不能含 O 和 I）。
2. 启动后端。真实模式的空数据库**没有示例成员**，要先在"成员"页添加。
3. 要用代码运行：先构建镜像 `docker build -t roundtable-sandbox backend/sandbox`，再在 `.env` 里设 `SANDBOX_ENABLED=1`。

**测试**

```bash
cd backend && python -m pytest -q                          # 离线测试，约 70 项
cd backend && python -m pytest -q --run-docker -m docker   # Docker 集成测试，需要镜像
cd frontend && npx tsc -b --noEmit && npx vite build
```

推送和 Pull Request 时，GitHub Actions 会自动跑后端离线测试和前端构建（`.github/workflows/ci.yml`）。

## 5. 容易踩的坑

- **环境变量优先于 `.env`。** 如果终端里已经有 `ANTHROPIC_BASE_URL`、`ANTHROPIC_AUTH_TOKEN` 等变量（比如在 Claude Code 里运行命令时），后端会静默使用它们，而不是 `.env` 里的配置。在 AI 助手里启动后端前，先 `env -u ANTHROPIC_AUTH_TOKEN -u ANTHROPIC_BASE_URL -u ANTHROPIC_API_KEY`。后端启动日志会打印实际使用的 Anthropic 地址，可以用来核对。
- **Claude 5.5 系列默认开启思考，思考的 tokens 也算在 `max_tokens` 里。** 所以后端不用 `max_tokens` 控制字数，字数要求写在提示词里。这几个模型也不接受 temperature 参数。
- **经中转站调用时**：Anthropic 的地址末尾**不要**加 `/v1`，OpenAI 的地址末尾**要**加 `/v1`。
- **后端是单进程的。** 房间的运行状态在内存里，重启时进行中的讨论会被标为 `error`，不要开多个 worker。
- **Windows 的 Git Bash 会自动改写以 `/` 开头的参数**（例如 `--base=/polylogue/`），需要时加 `MSYS_NO_PATHCONV=1`。

## 6. 我们一直以来的协作方式

这个项目由 Eutopia 发起，前端和接口契约由 Claude 编写，后端由 ChatGPT 编写，Eutopia 在两边之间传递代码和意见。核心规则只有一条：

> **前后端只靠接口契约连接。想改接口，先改 `docs/03-接口契约.md`（版本号 +0.1，写变更记录），再改代码。任何一方都不私下改字段。**

每一批工作的流程：写任务书 → 实现 → 另一方运行测试并审查 → 写审查意见 → 修改 → 提交。各批的任务书和审查意见都在 `docs/` 里，可以当作例子参考。

接手后可以按你的习惯安排你的 AI 助手，建议保留两点：
1. 接口契约由一方统一维护。
2. 每次改动通过 Pull Request 合并，由另一个人或另一个 AI 审查。

## 7. 已知问题和待办

| 项目 | 说明 |
|---|---|
| 部署配置 | 缺 docker-compose、反向代理、HTTPS 和部署说明。通过 HTTPS 访问时要设 `SESSION_COOKIE_SECURE=1` |
| 单进程 | 见上。数据量大了以后 SQLite 也需要定期备份 |
| 代码运行：漏写文件名 | 只有一个文件、模型又漏写 `path` 时，目前返回错误让模型自己补上。可以改成按语言自动补 `main.py` / `main.js` / `index.html`（可选） |
| Ollama 本地模型 | 需要成功调用一次才会显示为可用；默认按不支持工具调用处理，可以用 `TOOL_MODELS` 覆盖 |
| 模型下拉框 | 列表里没有的模型，可以在成员页"手动输入模型名"，也可以用 `.env` 的 `EXTRA_MODELS` 追加 |
| 原型文件 | `docs/01` 和 `styles.css` 提到的 `AI-Roundtable.html` 原型不在仓库里，不影响开发 |
