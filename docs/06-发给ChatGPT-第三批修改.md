**并发阶段打断后点"继续"，房间直接进入 `error`。** 交叉验证在回答阶段收到 `interrupt` 时，整批调用都被取消，`Crosscheck.run()` 拿到的回答全是 `None`，直接 `return False`；用户点继续后，`run_room` 按失败把状态设为 `error`。流水线执行阶段结构相同：不会报错，但所有稿件都变成"无可用稿件"，跳过审查后还标成 `finished`。现有测试只测了打断，没测打断之后再继续。复现步骤写在审查文件里。

契约已更新到 **v0.4**，第 3.4 节新增了并发阶段的规则：
- `interrupt`：取消这一批所有正在进行的调用，已输出部分保留并标记 `interrupted`，然后 `paused`。`resume` 后，**被打断的调用重新开始**（新消息、新 `seq`），已完成的结果保留，这一批完整结束后才进入下一阶段。
- `skip`：只取消当前那一个调用，不重做，这一批其余调用继续（和你现在的做法一致）。

请按这个顺序修改：

2. **建议**：需要 JSON 的步骤（规划、审查、互评、裁判打分）不要再追加"发言不超过 N 字""至少指出一个前面没人提到的问题或补充"，否则真实模型容易在 JSON 前后加文字导致解析失败；这些步骤的 `max_tokens` 单独放宽（至少 1200）。补一个测试：`parse` 不为空时，最后一条 user 消息不含"至少指出"。
