## 本次任务：契约 v0.5

真实使用时遇到两个问题：
- 中转站提供的模型（例如 `openai/gpt-6.1-sol`）不在 `MODEL_LABELS` 里，成员页的下拉框选不到。
- Claude 5.5 系列不接受 temperature 参数，成员页上的温度滑杆对它们完全不起作用（`docs/07` 第 2 条）。

契约已更新到 v0.5（见第 1 节的 `ModelOption`、第 2 节"成员与模型"下新增的三段，以及变更记录）。**前端已经完成并测试过**：
- 模型下拉框新增"手动输入模型名"，并检查 `服务商/模型名` 格式。
- 当 `supports_temperature === false` 时禁用温度滑杆，并提示"不支持调温度"。
- 如果后端还没返回这个字段，前端当作支持处理，所以先合并前端也不会出问题。

后端需要做的：

1. **`GET /api/models` 返回 `supports_temperature`。** 建议在 `llm.py` 里写一个明确的判断函数，不要依赖 LiteLLM 的模型表（新模型往往还没收录）：
   - `anthropic/claude-*-5-5`（Haiku、Sonnet、Opus 5.5）返回 `false`。
   - OpenAI 推理模型（`gpt-5`、`gpt-5-mini`、`gpt-5-nano` 等 `gpt-5*`，以及 `o` 系列）返回 `false`。
   - 其余模型（包括不认识的）返回 `true`。
   - 判断为 `false` 时，`stream_chat` 不传 temperature。`drop_params=True` 继续保留，作为兜底。
2. **`EXTRA_MODELS` 环境变量。**
   - 格式：逗号分隔的 `模型名=显示名`，例如 `EXTRA_MODELS=openai/gpt-6.1-sol=GPT-6.1 Sol`。
   - 用 `=` 分隔，因为 Ollama 的模型名里带 `:`。
   - 没写显示名时，用模型名里 `/` 后面的部分。
   - 和内置列表、成员正在用的模型合并去重。
   - 写进 `.env.example` 和 README。
3. **确认成员接口不校验模型是否在列表里。** 我看了 `schemas.py`，目前 `model` 字段只要求是文本，应该已经满足要求，请确认一下。
4. **离线测试：**
   - 设置 `EXTRA_MODELS` 后，`/api/models` 里能看到追加的模型和它的显示名。
   - Claude 5.5 和 `gpt-5*` 的 `supports_temperature` 为 `false`，DeepSeek 为 `true`。
   - `supports_temperature` 为 `false` 的模型，调用时的参数里没有 temperature（用 `FakeLLM` 记录参数来断言）。
   - 用列表外的模型名创建成员能成功。
