# 界面方案评估：AI-Roundtable.html

评估对象：`Desktop/AI-Roundtable.html`（单文件高保真原型，约 96 KB）
对照文档：《AI协作集群项目大纲.md》《AI协作集群-基于开源的开发方案.md》

## 结论

**视觉设计可以保留，代码要重写。**

- 作为设计稿，它质量很高：视觉语言统一，四种协作模式各有清楚的可视化，"AI 用圆角方块、人用圆形"这类细节也想到了。新前端直接沿用它的颜色、字体、间距和组件样式。
- 作为代码，它不能复用：所有数据写死，流式输出是 `setInterval` 模拟的，界面拼接全靠 `innerHTML`，没有状态管理，也没有接口层。接上真实后端等于重写，不如直接按开发方案用 React + Vite + TypeScript 重做。
- 范围偏大：知识库、工具开关、用量图表、存档、附件、导出都属于 M4，现在做出来会让人以为 M2 要交付这些。

## 问题清单

### A. 交互设计问题（重写时要改）

| # | 问题 | 改法 |
|---|---|---|
| A1 | 房间工具栏上能**随时切换协作模式**。但模式是房间创建时定下的，圆桌房间切到"辩论"会显示另一个房间的内容，逻辑不通 | 去掉切换器。模式是房间的固定属性，只显示标签 |
| A2 | 窗口宽度小于 1100px 时右侧检查器整个隐藏，**暂停、跳过按钮也跟着消失**。平板和手机上没法打断讨论，而插话和打断正是产品的核心卖点 | 暂停、打断、跳过移到工具栏，任何宽度都能点到 |
| A3 | 只有"暂停"和"跳过"。开发方案 4.2 节还要求"停止"：立刻取消正在输出的内容，保留已输出部分并标注"被打断" | 拆成三个操作：暂停（等当前发言说完）、打断（立刻截断）、跳过（截断后换下一位） |
| A4 | 交叉验证只有"各自回答 → 裁判"两步，缺了开发方案里的**匿名互评**（借鉴 LLM Council 的第二阶段） | 补上互评阶段，界面上把互评折叠在回答和裁判结论之间 |
| A5 | 交叉验证的"数轴"只适用于答案是一个数字的问题，换成"FastAPI 好还是 Node 好"就画不出来 | 去掉数轴，改成"共识点 / 分歧点"列表，由裁判输出 |
| A6 | 按 Esc 会暂停整张桌子，而 Esc 同时还负责关闭 @ 弹窗和新建房间弹窗，容易误触 | 去掉全局 Esc 暂停，只保留按钮 |
| A7 | 个人预算在设置页写的是"每月"，开发方案 4.4 节写的是"每日" | 统一为**每月**（和团队预算周期一致），接口契约里已定 |
| A8 | 新建房间时没法指定谁是正方、谁是裁判、谁是审查者，而辩论、流水线、交叉验证都依赖这些分工 | 新建房间弹窗按模式显示"职责"下拉框，默认自动分配 |

### B. 代码缺陷（说明原型不能直接改着用）

| # | 位置 | 问题 |
|---|---|---|
| B1 | `sendMsg()` | 发送者写死为"林"，任何人登录发出的消息都显示成林 |
| B2 | `sendMsg()` | @ 识别用的是 `@(\S+)`，名字带空格的成员（如"Llama 本地"）永远点不中 |
| B3 | 全文 | 名字、提示词直接拼进 `innerHTML` 和 `onclick="toast('${m.name}…')"`。接上真实数据后，名字里有引号或尖括号就会出错，甚至被注入脚本 |
| B4 | `openRoom()` | 用 `toggleAttribute('aria-current')` 设置的值是空字符串，而样式匹配的是 `aria-current="page"`，所以侧栏里当前房间永远不会高亮 |
| B5 | 用量页"按人" | 超支警告条件写成 `p[1]>40`（绝对金额），而不是"已用 / 上限"的比例，上限 ¥100 时花 ¥41 也会变橙色 |
| B6 | 多处 | 文案和数据对不上：首页说"阿哲和三个模型"，房间里实际坐了 4 个模型；成员页每个模型都写"在 4 个房间里" |
| B7 | 成员页 | 模型列表写死为 `claude-opus-4`、`gpt-5`、`gemini-2.5-pro` 等旧型号。模型更新很快，列表应由后端根据已配置的 Key 返回 |
| B8 | 登录页 | 邀请码前 4 位预填了 `RT7K` |

### C. 范围建议

| 页面 / 功能 | 建议阶段 | 本次前端是否实现 |
|---|---|---|
| 登录、房间列表、新建房间 | M2 | ✅ |
| 房间：圆桌模式 + 插话 / @ / 暂停 / 打断 | M2 | ✅ |
| 房间：流水线、交叉验证、辩论的展示 | M3 | ✅（界面先做好，后端按 M3 进度接入） |
| 成员配置 | M2 | ✅ |
| 用量与费用 | M2 | ✅（简化版：合计、按人、按房间、按日） |
| 设置：模型服务状态、邀请码 | M2 | ⏳ 下一批 |
| 存档 | M3 | ⏳ 房间列表里"已结束"筛选即可替代 |
| 知识库、工具开关、附件、导出 | M4 | ❌ 暂不做 |

## 保留的设计

- 颜色、字体、圆角、阴影等设计变量（`:root` 里那一组）
- 每个 AI 成员有固定身份色，AI 头像圆角方块、人的头像圆形
- 右侧检查器里的圆桌座位图，发言者的座位会亮起
- 圆桌模式的"第 N 轮"分隔线和汇总卡片
- 流水线的四列看板（规划 → 执行 → 审查 → 汇总）
- 辩论的左右两栏和裁判倾向条
- 新建房间弹窗的整体结构
